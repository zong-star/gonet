GONET · API V1

GoNet API 使用说明

查询园区网络设备、拓扑关系和 LLDP 物理链路，适用于 AI Agent、自动化巡检与第三方监控工具。

连接方式

基础地址
将示例中的 https://gonet.example 替换成客户端可访问的 GoNet HTTPS 域名或 IP。使用受信任的 TLS 证书。
凭据
在 API 管理页创建 Key，并把完整 Key 存入调用方的安全配置。下列命令从调用方环境变量 GONET_API_KEY 读取它，并在 Authorization: Bearer 请求头中发送。
查询权限
「精简拓扑查询」topology_compact 允许设备搜索、设备详情、设备邻居、接口状态、到核心的路径、拓扑摘要和采集诊断这七个 GET，与 Dify 的七个工具对应。完整拓扑另需「拓扑只读」topology_read 权限。
来源 IP
把 GoNet 实际看到的客户端出口地址加入该 Key 的白名单。经过 NAT 时使用 NAT 出口地址。经过反向代理时，由部署方配置可信代理。
请求与响应
GET 查询以 UTF-8 JSON 返回 data 和 meta。表中标注的 HEAD 适用于普通只读 Key 和管理员会话，响应体为空。

查询接口

当前有八个拓扑查询接口，其中七个作为 Dify 工具提供。完整拓扑接口未加入精简工具 Schema。

方法路径用途Dify 工具名
GET / HEAD/api/v1/topology完整拓扑未加入精简 Schema
GET / HEAD/api/v1/topology/summary拓扑统计get_topology_summary
GET/api/v1/devices按管理 IP、名称或 sysName 搜索内部设备 IDfind_device
GET / HEAD/api/v1/devices/{device_id}单台设备get_device_info
GET / HEAD/api/v1/devices/{device_id}/neighbors直接邻居get_device_neighbors
GET / HEAD/api/v1/devices/{device_id}/interfaces接口运行状态get_device_interfaces
GET/api/v1/devices/{device_id}/uplink-path到已配置核心设备的确认路径get_device_path_to_core
GET / HEAD/api/v1/topology/collection采集缺口和失败原因get_collection_diagnostics

完整拓扑、拓扑摘要、设备详情和设备邻居支持 state=all|active。普通查询默认 all，紧凑邻居默认 active。active 只保留状态为 active 的正式链路，设备列表仍包含历史设备，链路计数按筛选后的结果重算。未知、重复、空值或非法参数返回 400。

设备详情、设备邻居、上联路径和拓扑摘要的 GET 可通过 schema_version=2 选择新版响应，详见下节。各接口后续示例展示省略版本参数时的默认响应。

新版端点与单条上联路径

调用上述四个 GET 时显式发送 schema_version=2，响应使用 data.schema_version=2，外层仍为 data 和 meta。设备搜索使用现有契约，先取得唯一的内部设备 ID。新版字段和数据质量从 data 读取。

DEVICE_ID=102
curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  "https://gonet.example/api/v1/devices/${DEVICE_ID}/uplink-path?schema_version=2&target=core"

聚合适配与版本 3

邻居和上联路径支持 schema_version=3。路径的 aggregation.status 区分 confirmed、partial、unknown、none、conflict；member_data_status 单独说明列表完整度。未知或单端证据不能显示为无聚合。成员使用 from/to 和原有物理 link_id，双端确认后聚合只计一跳。v2 保留旧结构，并补充 aggregation_status / aggregation_diagnostics。

邻居 v2/v3 支持 neighbor_device_id 筛选与 cursor 翻页。has_more 为 true 时用 next_cursor 继续并保持原筛选和 limit；409 CURSOR_STALE 后重新查询。v3 的 response_truncated 表示字节裁剪，正常分页另由 has_more 表示。设备详情和摘要仍使用版本 2。

华为成员需由已验证的私有表适配采集；信锐核心的本端成员来源尚未核实，当前应保持 partial/unknown。

接口名称与端点

邻居的 local / remote、路径边的 from / to 和聚合成员共用以下端点字段。每个端点都携带所属设备的内部 ID。

字段含义
interface_name有可靠证据的真实接口名，未知为 null。端口主标签读取此字段。
interface_description管理员配置的描述或 IF-MIB ifAlias。已采到且为空时为 ""，缺证据时为 null。
if_index同设备、同观测批次内可靠关联的正整数索引，未知为 null。
interface_name_sourceinventory、if_name、lldp_interface_name 或 null，标明名称来源。
if_index_statusknown、not_collected、unmatched、ambiguous 或 unknown。索引非空时为 known。

接口名与索引可以独立缺失。只有描述的端点显示“接口名未知”，描述在详情中查看。历史字段缺证据时保留未知。

单条路径与状态

新版上联只返回至多一条确认路径。path_status=found 时，path 包含 target_core_device_id、hop_count、有序 nodes 和 edges，满足 hop_count = edges.length = nodes.length - 1。源设备即核心时返回一个节点、零条边。not_found 和 no_core_configured 返回 path=null 及原因。

max_paths 可省略或传 1，max_hops 为 1–16，默认 16。聚合边占一跳，成员放在 aggregation.member_links，member_data_status 区分完整、部分和未知。候选仅在 include_unverified=true 时单独返回，candidate_observer_device_ids 给出查询观察者范围。空数组表示可查且无记录，带原因的 null 表示无法提供。

verification_status 表示证据核验，topology_status 表示拓扑有效性，oper_status 表示运行观测。运行状态缺证据时为 unknown，其他运行状态须携带 oper_observed_at。

数据质量与计数

data_quality.snapshot_id 和 snapshot_at 对应实际读取的已提交快照，latest_scan 独立记录最近扫描。as_of、data_age_seconds、stale_after_seconds 和 stale 描述计算时间与时效。默认过期阈值为 72 小时，可由服务环境变量 GONET_TOPOLOGY_STALE_AFTER 配置。时间不可信时年龄和过期判断为 null，原因见 diagnostic_codes。

coverage 分别描述 network、device_neighbors 和 device_to_core_query 的覆盖，状态为 covered、gap 或 unknown。网络缺口和设备查询结果可同时展示。

新版邻居返回实际筛选条件、limit、matching_link_count、returned_link_count、returned_unique_neighbor_count 及 truncated。详情的 adjacent_link_count 和摘要的 count_definitions 提供计数口径。

主路径保持完整，必需响应超出 12 KiB 时返回 422 RESULT_TOO_LARGE，搜索预算耗尽时返回 422 SEARCH_BUDGET_EXCEEDED。控制台设备详情提供 SVG 和逐跳表格。Dify 的上联 OpenAPI 工具名为 get_device_path_to_core，客户端需核对实际发送的版本参数及端点字段。

完整拓扑

GET /api/v1/topology

无需路径参数。查询参数为 state 和 include_pending=true|false。后者默认为 true。设为 false 时，候选数组为空，摘要的待核验数量仍按可见候选计算。

data 包含统计 summary、核心设备 core_ids、设备 devices、物理链路 links 和待核验邻居 neighbor_candidates。完整图超过 2000 台设备、10000 条链路或 8 MiB 时返回 422。

curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  'https://gonet.example/api/v1/topology?state=all&include_pending=true'

拓扑摘要

GET /api/v1/topology/summary

无需路径参数，查询参数为 state。data 直接返回设备数、物理链路数、已采集设备数、历史设备数、待核验邻居数，以及按交换机、路由器和无线控制器分类的设备数。

curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  'https://gonet.example/api/v1/topology/summary?state=active'

设备搜索

GET /api/v1/devices

query 必填。管理 IP 按已核验地址精确匹配，支持 IPv4 和 IPv6。设备显示名和 sysName 依次按精确、前缀、子串匹配，忽略大小写。vendor 和 model 为可选的精确筛选条件。limit 范围 1–5，默认 5。

total 是截取前的去重命中数。ambiguous=true 表示最高匹配等级有多台设备，应先确认目标，再使用 items[].device_id 查询详情、邻居或到核心的路径。

curl --fail-with-body --get \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  --data-urlencode "query=192.0.2.20" \
  'https://gonet.example/api/v1/devices'

成功响应示例 · data 部分

{
  "items": [{
    "device_id": "102", "name": "接入交换机", "management_ip": "192.0.2.20",
    "vendor": "H3C", "model": "S5130", "match_type": "management_ip"
  }],
  "total": 1, "ambiguous": false
}

设备详情

GET /api/v1/devices/{device_id}

将 device_id 替换成设备搜索返回的 items[].device_id，或完整拓扑返回的 devices[].id。它是无前导零的正十进制字符串，最大值为 9223372036854775807。格式错误返回 400，设备不存在或不在可见范围内返回 404。查询参数为 state。

data.device 包含设备身份、系统名称、区域、厂商型号、管理地址、采集状态、发现深度、筛选后的链路数及最近观察时间。

DEVICE_ID=101
curl --fail-with-body \

设备邻居

GET /api/v1/devices/{device_id}/neighbors

路径参数沿用 设备详情 的字符串 ID，支持 state 和 limit。不存在或不可见的设备返回 404。已有设备没有匹配链路时返回 200 和空数组。

data 包含目标 device_id、去重后的 neighbor_count、物理链路数 link_count 和 items。每项为 neighbor 设备与 link 链路对象，同一邻居的并行物理链路分别列出。

精简 Key 自动使用紧凑响应，默认最多 20 条链路。普通只读 Key 或管理员会话可显式传入 limit=1–20 启用。紧凑响应增加从目标设备视角排列的 local、remote 端口、verification_status 和观测引用。returned_link_count 与 truncated 描述实际返回量，原有计数字段仍为截取前的总量。

DEVICE_ID=101
curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  "https://gonet.example/api/v1/devices/${DEVICE_ID}/neighbors?limit=20"

紧凑响应示例 · data 部分

{"device_id": "101", "neighbor_count": 0, "link_count": 0,
 "returned_link_count": 0, "truncated": false, "items": []}

接口状态

GET /api/v1/devices/{device_id}/interfaces，对应 Dify 工具 get_device_interfaces。

路径参数为设备搜索取得的内部 ID，无需 schema_version。返回 device_id、interfaces、status_collection_state 和 status_attempted_at。接口项包含名称、描述、ifIndex、admin_status、oper_status 和采集时间。该接口读取独立 IF-MIB 缓存，不触发扫描。

接口采集失败时保留上次成功值，并标记采集状态。unknown、采集失败或样本过期均不能直接解释为端口 down；拓扑 active 也不等于端口当前 up。

DEVICE_ID=68
curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  "https://gonet.example/api/v1/devices/${DEVICE_ID}/interfaces"

到核心的路径

GET /api/v1/devices/{device_id}/uplink-path

GoNet 在最新已提交的扫描批次内，沿已确认物理链路查找到可见核心设备的路径，优先返回跳数较少、证据较强的路径。双端确认的 LAG 占一跳，endpoint_a 和 endpoint_b 按路径方向排列，member_links 保留实际物理端口配对及链路 ID。

target
仅支持 core，默认值也是 core。
max_paths
范围 1–3，默认 3。
max_hops
范围 1–16，默认 16。起点已是核心时可返回零跳路径。
include_unverified
默认 false。设为 true 时最多附带 20 条待核验观察，单列于 candidate_links。路径仍按已确认链路计算。
DEVICE_ID=102
curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  "https://gonet.example/api/v1/devices/${DEVICE_ID}/uplink-path?max_paths=3&include_unverified=true"

path_found=false 时返回空 paths 和 reason。例如 no_confirmed_path_to_core 表示在当前批次和跳数范围内没有找到确认路径。coverage_gap=true 表示采集覆盖有缺口，search_truncated=true 表示搜索达到工作预算。

采集诊断

GET /api/v1/topology/collection，对应 Dify 工具 get_collection_diagnostics。

使用 schema_version=2。可选参数：device_id 筛选正式设备；snapshot_id 检查当前快照一致性；limit=1–50 控制单页数量，默认 10；cursor 使用上一页 next_cursor。快照或游标对应数据变化时返回 409，需要重新查询。

响应 data.items 包含设备、未解析邻居和目标尝试，提供名称、地址、采集状态、覆盖状态、reason_codes 和 incomplete_components。total 为匹配项总数；has_more=true 时继续翻页。不同类型和口径的计数不可相加，not_recorded 不等于已知采集失败。snapshot_id 不提供任意历史查询。

curl --fail-with-body \
  -H "Authorization: Bearer ${GONET_API_KEY}" \
  'https://gonet.example/api/v1/topology/collection?schema_version=2&device_id=68&limit=10'

数据与标识

  • 查询读取现有管理范围内最近一次已提交的扫描结果和保留的历史状态。扫描提交前，查询仍读取上一份已提交数据。查询过程无需登录交换机、启动扫描或下发配置。
  • 待核验邻居是 LLDP 观察，记录包含 key、system_name、device_kind、model、status、observed_by_ids 和 observed_at。它单独列出，等待核验后才可能成为正式设备。
  • 正式设备、端口、链路和扫描 ID 都是十进制字符串。access_addresses 是访问地址。候选 key 用于标识待核验观察，设备详情路径接受正式设备 ID。
  • 每条链路有独立 id，记录两端设备和端口的 ID、名称，以及 confidence、discovery_state、fresh、coverage_gap、missed_complete_scans、首次和最近观察时间及扫描 ID。
  • meta 包含请求 ID、接口版本、生成时间、最近提交扫描的 ID、状态、完成时间、数据年龄、fresh、coverage_gap 和查询使用的 state。缺失时间与扫描 ID 可为 null。fresh 描述数据与扫描的关系，实时在线状态需另行判断。
  • v2 及以上邻居、路径响应的 data_quality.collection 提供采集计数、问题码和明细地址；v2 摘要与设备详情也提供这些字段。调用 GET /api/v1/topology/collection?schema_version=2 分页查看设备、未解析邻居及失败目标；可加 device_id 筛选，并用 snapshot_id 检查快照一致性。按 next_cursor 翻页。计数口径不同，不可直接相加。
  • partial 表示扫描存在缺口，可能涉及设备失败、表项不完整、身份或端口未解析、扫描限制。unknown 表示完整性证据不足，响应会给出具体原因。路径覆盖检查指定跳数内的可见 active 分支，核心作为终点；已找到确认路径与采集存在缺口可以同时成立。旧 Dify 工具可重新导入最新 Agent OpenAPI，增加 get_collection_diagnostics。
  • 设备搜索、紧凑邻居、路径及精简 Key 的查询受 12 KiB 响应上限约束。meta.response_truncated=true 表示省略了部分候选观察、列表项或排名靠后的整条路径。单条必需结果仍超限时返回 422。

错误码与排障

{"error":{"code":"IP_NOT_ALLOWED","message":"请求来源 IP 不在白名单内"},"meta":{"request_id":"example-request"}}
HTTP含义与检查项
200查询成功。空列表可以表示当前范围内没有匹配的数据。
400检查参数名、参数值以及从设备搜索或拓扑取得的内部设备 ID。
401缺少凭据或 Key 无效。检查 Bearer 前缀、完整 Key 以及代理是否转发 Authorization。
403检查 Key 的来源 IP 白名单和入口限制。精简 Key 请求完整拓扑时返回 API_ROUTE_NOT_ALLOWED。
404检查接口路径、设备 ID 和设备是否在可见范围内。
405请按接口表使用 GET 或 HEAD。精简 Key、设备搜索和到核心的路径均使用 GET。
422RESULT_TOO_LARGE 表示响应超出容量。新版上联的 SEARCH_BUDGET_EXCEEDED 表示搜索预算耗尽，无法确定选路结果。
500 / 503 / 504服务内部异常、数据源不可用或读取超时。排查时可提供 meta.request_id。

OpenAPI

通用 OpenAPI 3.1.1 覆盖全部接口。精简 OpenAPI 3.0.3 提供七个只读查询工具、Bearer 鉴权和响应定义；不含完整拓扑接口。
